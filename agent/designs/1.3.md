# 1.3 Phone safe defaults

Architect design, 2026-11-04. Waiting for "OK, build 1.3".

## How it works today
- **Token.** `load_token()` at `phone.py:63-70` creates a value with `secrets.token_urlsafe(24)` and stores it in `%LOCALAPPDATA%\HybridAI\phone_token.txt` (`phone.py:51`). `PhoneServer.__init__` keeps a copy in `self.token` (`phone.py:111`).
- **Auth.** `_authed` (`phone.py:203-206`) checks `Authorization: Bearer <token>` with `hmac.compare_digest`. A wrong token gets 401, and the phone then shows "isn't paired... Pair again" (`mobile/app.js:55`).
- **Pairing.** `/pair` only opens on the laptop itself, with no proxy headers (`phone.py:208-212`, `526-531`). The page shows `links()` (`phone.py:143-148`): `http://<ip>:8765/#token=…` for each LAN or Tailscale 100.x address, but only when `lan` is on. If `public_url` is set, its link goes first. The phone saves the token in localStorage as `hai_token` (`app.js:19-21`, `41`). localStorage is separate for each origin (address).
- **Signed links.** `sign(path, kind)` (`phone.py:151-152`) is the first 32 hex characters of HMAC-SHA256 with the token as key, over `"kind:path"`. There are three kinds:
  - `"f"`: download links `/api/file?p=&s=`. Made by `file_link` (`154-156`), used by `tools.py:87,109` (`/find`, `/screenshot`), checked in `_file` (`485-492`). They need no Bearer header because `<img>` and `<a>` tags open them.
  - `"a"`: "ask about it" links `attach:p=&s=`. Made by `ask_link` (`158-160`), checked in `_chat` (`356-361`).
  - `"u"`: upload ids `sig:basename`. Made at `324`, checked in `_resolve_upload` (`327-333`).

  These links have **no expiry**. They are saved inside assistant replies in chats.db and stay valid until the token changes.
- **Reset.** A reset already exists: the "Disconnect all phones" button (`ui/inspector.py:271-274`) calls `app.reset_phone_token` (`app.py:1017-1023`), which calls `PhoneServer.reset_token` (`phone.py:139-141`). Each request reads `srv.token`, so a running server rejects old tokens and links at once. There is no confirmation dialog.
- **Defaults.** `phone.enabled` already defaults to False (`settings.py:53`), so a fresh install already has the server off. `phone.lan` defaults to True (`settings.py:55`), with `True` fallbacks at `app.py:999` and `ui/inspector.py:256`. `lan` decides where the server listens: `0.0.0.0` or `127.0.0.1` (`phone.py:123`).

## 1. `phone.lan` off by default
- `settings.py:55` becomes `"lan": False`. The fallbacks at `app.py:999` and `inspector.py:256` become `False`.
- **Existing users.** Settings are saved in full, so `"lan": true` is already in their file and the new default never applies to them. Recommended: a settings_version 2 upgrade in `Settings._upgrade`:
  - If `phone.enabled` is False, set `lan` to False. The server is off, so this breaks nothing.
  - If `phone.enabled` is True, keep `lan` as it is and log one line: "Phone is reachable on Wi-Fi; turn it off in Settings → Phone for safety."
  - Before the upgrade saves, copy the file once to `settings.v1.bak` (CLAUDE.md: back up before migrating).
  - Why: a saved `true` cannot be told apart from the old default. Silently cutting off a phone you use every day is worse than leaving one switch for you to flip.
- **Your paired phone if `lan` turns off.** The settings change restarts the server (`app.py:374-375`), now listening on `127.0.0.1:8765` only.
  - **Phone opened from `http://192.168.x.x:8765` or `http://100.x.x.x:8765`:** the connection is refused. API calls fail as network errors, not 401. The installed app still opens from the service-worker cache but cannot chat. Download links in old chats fail the same way.
  - **Token:** unchanged and still valid. Turning `lan` back on brings the phone back with no re-pairing.
  - **`tailscale serve` / `public_url` (`https://<laptop>.<tailnet>.ts.net`):** keeps working, because `tailscale serve` forwards to `127.0.0.1:8765`. If serve was set up against the 100.x address instead, it breaks too.
  - **What you must do:**
    1. Run `tailscale serve --bg 8765` once.
    2. Paste the https address into Settings → Phone.
    3. Click "Pair a phone (QR)" and open the https link on the phone. It is a new address, so localStorage is empty there; the token is the same.
    4. Install the app again from that address and remove the old home-screen icon.
- **Pair page.** Change the "no address found" note (`mobile/pair.html:29`) to point to `tailscale serve` plus the Tailscale HTTPS address, or the Wi-Fi switch. Rename the button mentioned in `pair.html:27` to "Reset phone token".

## 2. Links expire after 1 hour
- In `phone.py`, add `LINK_TTL = 3600`. Signatures become `hmac(token, f"v2|{kind}|{exp}|{path}")`, full 64 hex. `exp` is a whole-second Unix time. The path goes last, so the message cannot be read two ways.
- **New helpers:**
  - `sign(path, kind, exp)`
  - `make_sig(path, kind, now=None) -> (exp, sig)`
  - `check_link(path, kind, exp, sig, now=None) -> "ok" | "expired" | "invalid"`

  `check_link` rejects an `exp` that is not all digits, runs `compare_digest` **before** looking at the time, and only then tests `now > exp`. The `now` argument exists so tests can control time.
- **Link formats:**
  - `file_link`: `/api/file?p=&e=&s=`
  - `ask_link`: `attach:p=&e=&s=`
  - upload id: `sig:exp:basename`. Upload names cannot contain `:` (`phone.py:307`).
- **Verifying:**
  - `_file`: invalid gives 403 `{"error":"link not valid"}`; expired gives 403 `{"error":"link expired - run the command again on the phone"}`.
  - `_chat`: an expired attach link adds the notice "a file link expired, run /find again"; an expired upload id gives the existing "an upload expired" (`phone.py:350`).
- **Old links fail.** Links made before this change have no `e` and use the old message format, so they always come back "invalid" (403). The same happens to links in old chats an hour after they were made.
- **Clock.** The same process both signs and checks, using `time.time()`; a monotonic clock would not survive restarts. If the clock jumps backwards, a link lives a bit longer, never forever. Nothing is shared with the phone's clock.
- **What the phone sees.** A screenshot `<img>` shows as broken. A tapped download link opens a JSON error page. Changing `app.js` is optional and out of scope.

## 3. "Reset phone token" button
- `ui/inspector.py:271` changes to the text "Reset phone token", with a note: "Disconnects every paired phone and makes all links invalid."
- `app.reset_phone_token` first asks `dialogs.ask(self, "Reset phone token?", "Every paired phone will be disconnected and must pair again.", [("reset","Reset token"),("cancel","Cancel")], primary="cancel")`. Only "reset" goes ahead.
- What it regenerates: a new token in `phone_token.txt`. Make the write atomic: tmp file, then `os.replace`. If the server is running, also update `srv.token`.
- Old Bearer tokens, all f/a/u links and upload ids then fail on the very next request, because the HMAC key changed. There are no cookies or sessions to clear. A reply already streaming finishes; that is accepted.
- Afterwards: `dialogs.info` "Phone token reset. Click 'Pair a phone (QR)' and open the new link on your phone." The existing inspector log line stays, and the token is never logged.
- Threads: this all runs on the Tk thread from the button. It is one small file write and starts no worker thread, so the `self.events` queue is not needed. Update the docstring at `phone.py:15`.

## Risks
- After the upgrade you may lose phone access if you only ever used the Wi-Fi/100.x address (only if the phone was off at upgrade time and you later turn it on).
- Shared screenshots and links in old chats stop working after an hour; this is intended.
- `tailscale serve` pointed at the 100.x address breaks when `lan` is off.
- Changing the Tk dialog flow has no automated test.
