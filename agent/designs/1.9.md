# 1.9 Single running copy, and a safe legacy migration

Architect design, 2026-11-04. Waiting for "OK, build 1.9".

## Context (verified)
- `migrate_legacy` (`config.py:48-87`) moves only `project\data\chats.db` (with its -wal and -shm) and `project\.env`. It does not touch `memory.db` or `reminders.db`, which are already in DATA_DIR. It makes **no backup** today.
- `app.py:38-42` already wraps it in `except Exception`, so there is no traceback dialog, but under pythonw the user sees nothing.
- The real bug is at `config.py:67`. `shutil.move` tries a rename; if another process holds the file, the rename fails, so it copies the file and then the unlink fails with PermissionError. That copy may miss rows still in the other process's WAL (the checkpoint at `:63` returns "busy" silently).
- Result: `DB_PATH` exists, the old file is left behind, and every later start says "old chats left in place". The user is stuck on an incomplete copy. The `.env` move at `:85` has the same partial-copy problem.
- pywin32 is not in requirements.txt or the venv. Not used: ctypes and the standard library only.
- CI runs on windows-latest, so tests must never open a real message box.

## 1. Single-instance mechanism: a named mutex via ctypes
- `CreateMutexW(None, False, name)`, then `GetLastError() == 183` (ERROR_ALREADY_EXISTS). kernel32 loaded with `use_last_error=True`.
- Name: `Local\HybridAI-<sha1(normcase(abspath(config.DATA_DIR)))[:16]>`. Handle kept in a module global, never closed.
- Why not the alternatives: a lock file goes stale after a crash; port 8765 is a poor lock (the phone server is off by default since 1.3, and `allow_reuse_address` may let a second process bind on Windows).
- **Stale lock after a crash:** none. The kernel closes all handles when a process dies, even if killed. The handle is not inheritable.
- **Multiple Windows users:** `Local\` is per session and each user has their own %LOCALAPPDATA%, so each user gets their own copy.
- **Keyed on DATA_DIR:** tests with a temp `HYBRID_AI_DATA_DIR` never collide with the real running app.
- **pythonw, launch.bat, `python app.py`, other clones:** same name, all blocked.
- **What the second copy does:**
  1. Shows `MessageBoxW` (MB_OK | MB_ICONINFORMATION | MB_SETFOREGROUND), before Tk loads: "Hybrid AI is already running. Switching to it. If you can't see it, it may still be starting; if it is stuck, end pythonw.exe in Task Manager."
  2. Brings the first window forward: `FindWindowW("TkTopLevel", "Hybrid AI Assistant")`, `ShowWindow(SW_RESTORE)` if minimised, `SetForegroundWindow`.
  3. `sys.exit(0)`.
- **Test switch:** with env var `HYBRIDAI_NO_DIALOGS=1` the message goes to stderr instead of a box.
- **Where it runs:** top of app.py, right after `import config` (side-effect free), before `import customtkinter`, `log_setup.setup_safe()`, `migrate_legacy` and any DB open. Guarded by `if __name__ == "__main__":`, so `import app` in tests never takes the mutex. The second copy creates no folder, opens no DB and never rotates `app.log`.

## 2. migrate_legacy, redesigned (config.py)
`MigrationStopped(Exception)` carries `.message`, the text the user sees. It is raised only while the old files are untouched and `DB_PATH` does not exist. Steps for chats.db (only when LEGACY_DB exists and DB_PATH does not):
1. **Clean up an earlier crash:** remove a leftover `DATA_DIR\chats.db.migrating` (only we create it).
2. **Is the file held?** `CreateFileW(GENERIC_READ, share=0)` on chats.db and any -wal/-shm. Error 32 or 33 → MigrationStopped: "Your old chats in <path> are open in another program (an older Hybrid AI, a DB viewer, OneDrive). Close it and click Retry. Nothing was changed."
3. **Free space:** `shutil.disk_usage(DATA_DIR)` must have ≥ 2 × (total size + 10 MB). Otherwise MigrationStopped.
4. **Back up, before SQLite opens the file:** `shutil.copy2` the raw bytes to `BACKUP_DIR\migration-YYYYmmdd-HHMMSS\` (chats.db, chats.db-wal, chats.db-shm, whichever exist), then check each size matches. If any copy or check fails: delete that backup folder, MigrationStopped ("couldn't back up your old chats; nothing was moved"), **refuse to migrate**. A due `.env` move is backed up into the same folder.
5. **Copy:** open the old file with `sqlite3`, `src.backup(dst)` into `chats.db.migrating`, `PRAGMA quick_check`, row counts in `conversations` and `turns` must match the source. The backup API reads through the WAL, so the checkpoint is no longer relied on. Any error: delete `.migrating`, MigrationStopped.
6. **Commit:** `os.replace(.migrating, DB_PATH)` (atomic in the same folder). PermissionError/OSError: clean up, MigrationStopped.
7. **Delete the old files:** chats.db, -wal, -shm, then rmdir. Not fatal. On OSError the note says: "Chats moved to <DB_PATH>. Couldn't remove the old copy at <path> (in use); you can delete it."
8. **.env:** copy to `ENV_PATH.tmp`, `os.replace` into place, remove the old one. OSError before the replace → note: "API keys stay in the project folder this time." `load_env` already falls back to LEGACY_ENV; nothing partial is left.

**app.py:** the module-level call becomes `startup.migrate_or_exit()`. It loops: on MigrationStopped it shows `MessageBoxW` with MB_RETRYCANCEL. Retry runs the migration again; Cancel calls `sys.exit(0)` before `Store(DB_PATH)` can create an empty chats.db that would strand the old chats. The current `except Exception` stays as a last resort.

## Required answers
- **What is backed up:** the raw old chats.db, -wal and -shm (whichever exist), plus .env, in `%LOCALAPPDATA%\HybridAI\backups\migration-<timestamp>\`, taken before any SQLite open. **If the backup fails, the migration is refused.** memory.db is not migrated, so it needs no backup in this step.
- **Closed or crashed mid-migration:**
  - Before step 6: old files intact, DB_PATH absent → next start removes `.migrating` and redoes everything.
  - Between steps 6 and 7: both copies exist; the existing "old chats left in place" note shows. No data lost.
  - During step 7: at worst an orphan -wal stays in the project folder; its content is already in DB_PATH.
- **Safe to run twice:** yes. Once the old file is gone it does nothing. A retry after MigrationStopped makes a new timestamped backup.
- **Rollback:** close the app, copy the files from `backups\migration-*` back to `<project>\data\`, delete `%LOCALAPPDATA%\HybridAI\chats.db`. The step-7 note names the backup folder.
- **Time for ~2,000 chats:** whole chats stored as JSON, ~20-50 KB each → ~40-100 MB file. On an SSD with antivirus at 100-300 MB/s: raw backup ~0.3-1 s, SQLite backup API ~0.3-1 s, quick_check ~0.2-0.5 s; **total ~1-3 s, once only**. **1,000 summaries:** memory.db is not touched, 0 s.

## 4. Tests (temp folders only, via the existing `env` fixture)
**tests/test_migration.py:**
- Held file: a `sqlite3` connection open on the old chats.db in WAL mode → MigrationStopped; old file's hash unchanged, no DB_PATH, no backup folder.
- `config.os.replace` raises PermissionError → MigrationStopped; old file intact, no DB_PATH, no `.migrating`.
- `shutil.copy2` raises OSError → MigrationStopped; no partial backup folder; old file intact.
- Backup contents: folder holds chats.db and -wal; a row that exists only in the WAL is readable from both the backup and the migrated DB.
- Stale `chats.db.migrating` → next run succeeds.
- `os.remove` raises for the old path → DB_PATH has the data, note says "you can delete it", nothing raised.
- `.env`: an `os.replace` failure leaves the old .env and no ENV_PATH or tmp file.
- Existing `test_core.py:43, :77, :347` still pass.

**tests/test_startup.py:**
- Subprocess child holds `acquire_single(name)` with a unique test name; the test gets False; after `proc.kill()` it gets True (no stale lock).
- End-to-end: hold the mutex for a temp DATA_DIR, run `python app.py` with `HYBRID_AI_DATA_DIR` set there and `HYBRIDAI_NO_DIALOGS=1`; exits 0 within 10 s, prints "already running" on stderr, does not create the temp data folder.
- `migrate_or_exit` with a fake `ask`: retry then success works; cancel raises SystemExit and creates no chats.db.

## 5. Risks and open questions (recommendation)
1. The backup keeps a second copy of your chats; DECISIONS says "move only" but CLAUDE.md requires a backup. *Keep the backup in the private folder; record it in DECISIONS.md; cleanup later.*
2. Same user in two sessions (console and RDP) isn't caught by `Local\`. *Accept; `Global\` adds edge cases for no real benefit.*
3. Window lookup depends on the title "Hybrid AI Assistant". If it changes, focusing silently does nothing but the message still shows. *Accept; share a title constant with app.py.*
4. Short gap between the held-file check and the copy. *Covered: a later failure still raises MigrationStopped or leaves data safe.*
5. Cancel exits the app. *Yes, exit; starting with an empty store would strand the old chats.*
6. `HYBRIDAI_NO_DIALOGS` is a test-only switch. *Accept; document it in RUNBOOK.*
7. New `except` blocks must log, or `test_no_silent_except` fails.
