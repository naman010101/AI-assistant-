# 1.4 Cloud privacy filter

Architect design, 2026-11-04. Waiting for "OK, build 1.4".

## Where it sits
There is one choke point: `router.stream_chat`, between `prepare(...)` and `_stream(...)`. Every cloud call site goes through it:
- `app.py:602` `_generate`. This is the main chat; the code explainer (`app.py:1426` via `build`) uses it too.
- `app.py:1355` `quick_ask_worker`.
- `phone.py:435` `_chat`.

No code calls `gemini_client`, `groq_client` or `chat.completions` directly except `router._stream`. Memory summaries, the context digest (`memory.ollama_completer`) and OCR all run locally. `editor.py` and `codeexplain.py` never call a model. The `*_backup.py` files are not imported anywhere.

The rule in `stream_chat`:
```
payload = prepare(route_name, messages, system, fit_args, on_context)
if mask_cloud and client is not local_client:
    payload, masker = privacy.mask_messages(payload)
    if on_masked and masker.report(): on_masked(masker.report())
```
- The test is `client is not local_client`, not the model name, so it does not depend on how model IDs are stored (step 1.2).
- `mask_messages` works on a deep copy. `conv.history` itself is never changed.
- The local fallback calls `prepare` again on the raw history, so local models always get the unmasked text.
- `mask_cloud` defaults to True. A call site that forgets the flag still masks.
- Masking runs after `context.fit`, so one place covers the current message, earlier history, the digest, the system prompt, memory notes, editor instructions and attachment text.

## What gets masked (new module `privacy.py`)
access.py has no patterns for text content. It only has `SECRET_NAMES` and `SECRET_DIRS` (`access.py:22-29`), which match file names. So:
- `privacy.py` imports `access.SECRET_NAMES` for the rule "a path whose file name is a secrets file is masked whole". No refactor of access.py is needed.
- The email regex is copied from `router.PII_PATTERNS[2]` (`router.py:58`), with its bug fixed (`[A-Z|a-z]` lets `|` into the domain ending).

Placeholders are numbered by first appearance across the whole request; identical values share a number.

| Kind | Placeholder | Patterns |
|---|---|---|
| Email | `[EMAIL_1]` | fixed regex above |
| API key | `[API_KEY_1]` | prefixes only: `sk-`/`sk-proj-`/`sk-ant-`, `AIza…{35}`, `gsk_`, `gh[pousr]_`, `github_pat_`, `AKIA`/`ASIA`+16, `xox[abprs]-`, `sk_live_`/`rk_live_`, `hf_` |
| Token | `[TOKEN_1]` | `Bearer <16+ chars>` (the word "Bearer" is kept), JWT `eyJ….eyJ….…`, the password in `scheme://user:pass@host` |
| Private key | `[PRIVATE_KEY_1]` | a whole `-----BEGIN … PRIVATE KEY-----…END…` block |
| Secret value | `[SECRET_1]` | the value in `api_key|secret|token|password|passwd|pwd|client_secret|access_key … [:=] value` |
| Path | `[PATH_1]` | see below |

**Secret value rule.** Only the value is replaced. A value is skipped when it is shorter than 8 characters, all digits, contains `(`, or is a bare dotted identifier such as `os.environ.get` or `settings.key`.

**Paths.** Matched forms: drive paths (`C:\…`, `C:/…`), UNC (`\\server\share\…`), `%VAR%\…` and `~\…`, `file:///C:/…`, `/c/Users/<name>/…` and `/home/<name>/…`.
- The folder part is replaced and the file name kept: `C:\Users\<you>\Documents\app.py` becomes `[PATH_1]\app.py`, so tracebacks and "fix app.py" still make sense.
- If the file name matches `SECRET_NAMES`, the whole path is masked.
- The home folder (`os.path.expanduser("~")`, either slash style, any case) is matched first, so a username with a space is caught.
- Unquoted paths end at whitespace; quoted paths end at the closing quote.
- The username is masked only inside paths, not in normal sentences.

**Un-masking the reply: yes, locally, while it streams.**
- `Unmasker.feed(tok)` holds back a trailing `[` plus up to 24 characters until it knows whether they form a placeholder; `flush()` runs at the end. Matching is case-insensitive.
- `on_token`, the saved answer and the history all get the real values.
- Why: your data only comes back to your own machine; edit blocks would otherwise write `[API_KEY_1]` or `[PATH_1]` into your file; the next turn masks the history again from scratch.
- Placeholders the model invents that are not in the map are left as they are.

## File attachments and pasted code
- **Text, code, PDF, docx and notebook attachments** become text parts in `attachments.build_message`, so they are masked like everything else, including the `path="…"` attribute in the `<file …>` tag.
- **Images** cannot be masked. Only `type=="text"` parts are masked; `image_url` data URLs pass through untouched and the notice says "1 image sent as-is".
- **The `cloud_files` setting** is unchanged in meaning: `block` still blocks; `ask` still asks, with one more line in its dialog (`app.py:499`): "Emails, keys and paths in the text are masked first. Images are sent as they are."; `allow` sends with masking.
- **Pasted code is masked too**, because keys in code are the most common leak. To keep false positives low there is no "high-entropy", long-hex or base64 rule, so SHA hashes, UUIDs, git SHAs and base64 blobs are never touched. Only fixed provider prefixes, PEM blocks, JWT, Bearer, `user:pass@` and the name-plus-value rule fire.

## Showing what was masked
- `masker.report()` gives `{"counts": {"email": 1, "api_key": 1, "path": 2}, "items": [{"ph": "[API_KEY_1]", "kind": "api_key", "preview": "sk-…7f3a"}]}`. Key/token/secret previews show only the first 3 and last 4 characters; emails and paths are shown in full (local UI only).
- **Desktop:** `work()` passes `on_masked=lambda r: q.put((gen_id, "masked", r))`. `_poll` gets an `ev[1] == "masked"` branch that stores it in `self.gen["masked"]`, placed before the `else: done = …` (`app.py:656`) so it isn't taken as "done". `_on_done` calls a new `AssistantMessage.set_masked(report)` (next to `set_memory`, `ui/chat_view.py:199`) showing "Masked before sending: 1 email, 1 API key, 2 paths" with a "Details" toggle. Only counts are saved in `turn["masked"]`; the log line has counts only.
- **Quick Ask:** counts go to a log event and a notice line in the popup.
- **Phone:** `emit({"type": "notice", "text": "Masked before sending: …"})`; app.js already shows notices.
- **Never logged:** raw values or previews.

## Setting
`"privacy_filter": True` in `settings.DEFAULTS`, with a switch in the inspector's "Files and the cloud" section (`ui/inspector.py:365`). The three call sites pass `mask_cloud=settings.get("privacy_filter", True)`. When it is off, the inspector log shows a warning on each cloud send.

## Tests (`tests/test_privacy.py`)
1. **Fake key reaches the cloud masked.** Fake client for `cloud-groq` records `kw["messages"]` and streams back "use [API_KEY_1]". Send "my key is sk-proj-FAKEabc123…". The key is in none of the recorded messages; `[API_KEY_1]` is; `on_masked` counts are `{"api_key": 1}`; the returned text and `history[-1]` contain the real key; `history[-2]` still holds the raw user text.
2. The same message to `local-general` arrives unmasked; `on_masked` not called.
3. Cloud failure falls back to local: the local fake receives the unmasked text.
4. Each kind is caught and numbered stably: email, each key prefix, Bearer, JWT, PEM, `password = "hunter2hunter2"`, home path → `[PATH_1]\x.py`, UNC, `%APPDATA%\…`, `C:\…\.env` masked whole; the same email twice gives one placeholder.
5. False positives stay unmasked: sha256 hex, UUID, git SHA, base64 blob, `token = os.environ.get("X")`, `@app.route`, `pkg@1.2.3`.
6. System text, a digest message and a `build_message` file block are masked; an `image_url` part is byte-for-byte unchanged.
7. Unmasker: a placeholder split across chunks (`"[API_"`, `"KEY_1]"`) un-masks; unknown `[FOO_9]` passes through.
8. `mask_cloud=False` sends the raw text.
9. A `masked` event in `_poll` does not end the generation.

## Risks
- **Missed secrets.** Keys with no known prefix, secrets in prose ("my password is x"), phone numbers slip through. The notice could make you feel safer than you are.
- **False positives.** The name-plus-value rule masks test fixtures; paths in docs get masked. Harmless because of local un-masking, but the model sees less.
- **Mangled placeholders.** The model may alter a placeholder so un-masking fails and an edit block keeps it. A leftover-placeholder warning in `editor.checks` is a possible later step.
- **Speed.** Regex over large attachments should be well under 50 ms but needs measuring.
- **Out of scope.** The web search in `tools.py:115` sends queries to DuckDuckGo unfiltered; it isn't a model call.
